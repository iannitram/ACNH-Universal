# Roadmap

Updated: 2026-11-24

features:
- housekeeping: Build verification, release hygiene and upstream sync
- engine-core: Game preparation, launch, backups and save-relay adapters
- faces: Command line and controller-first Slint launcher
- recompiler: Rust AArch64 loader, analysis, C++ emitter and driver
- runtime: Rust host runtime behind the game ABI
- hubs: Discovery, paired transfer and fleet records on the home network
- steamos: Contained local builds and Game Mode on Linux and SteamOS
- windows: Contained local builds and controller play on Windows
- apple: Contained Mac and iOS builds, SideStore, controllers and saves
- android: Adreno build, private game storage, controller and save support
- one-island: The same island across all six devices
- design-pass: Final launcher and Game Mode design review
- resolution: Responsive rendering, HUD and safe areas across displays

From `SPEC.md` (approved 2026-11-02; M5 widened and approved again 2026-11-17; M4 and the Dropbox exception changed and approved again 2026-11-18; M18 added and approved 2026-11-18; M18, M4 and the Dropbox exception changed 2026-11-23 for an in-app download from my own Dropbox, and the SPEC as changed in PR #232 approved again the same day: "Approve, keep big .ipa") to 1.0: *Animal Crossing: New Horizons* 3.0.2, 3.0.3, 2.0.7 or 1.0.0, built from my own game folder, on the AMD handheld, the Strix Halo tablet, the RTX 3090 Ti desktop, a Mac, an iPhone or iPad, and an Adreno Android device; a week of island life on the AMD handheld (M12); the same island on each through save-relay; and our code in Rust. The code map is `docs/code-map.md`, the words are `GLOSSARY.md`, the decisions are `docs/adr/` (0001 workspace, 0002 prep tools then recompiler then runtime to Rust, 0003 Slint launcher, 0004 build hubs, 0005 Android keeps upstream's route, 0006 Apple builds the same recompiled code), the upstream and peers are in `PEERS.md`. Every piece is an issue titled `<id>: ...`; `Blocked by` in each issue sets the order.

Where things stand on 2026-11-24, after Waves 1–8: the 1.0 Rust and platform code build-out on Linux/Windows/Android is complete in `main` (`de04bcd`). All 11 runtime groups (`Config`, `Time`, `Saves`, `Files`, `Input`, `Audio`, `Services`, `Kernel`, `Memory`, `Platform`, `Loader`) are ported to Rust (`crates/runtime/src/*.rs` + `runtime/src/*_wrapper.cpp`, with Android NDK `cbindgen` FFI fixes in PR #312). The Rust recompiler (`crates/recomp`, #49) is cut over, and Python `recomp/`, `tools/setup_acnh.py` (#34), the legacy `launcher/` (#44), upstream's `build.yml` + `package_release_*.sh` (#174), and `recomp_source_test` (#247, keeping `nx_recomp`/`recomp_test` for `nx_prepare`/Android) are retired. Also landed: Windows CI (`cpp-windows` on `windows-2025`, #70), Windows and Linux contained app folders (`pack_folder.rs`, #190, #191), Resolution Independence (`nvn_aspect`, #91), Android/Mali perf optimizations (#268), Android private storage (`<files>/game/`, #192), Android hub pull (#80), resumable Dropbox download (`appgame::download`, `GameDownloadJob`, `android` Prepare target, #230), Android pad prompts & hot-plug (#173), USB/headphone audio disconnect reopen thread (#255), and the feature-gated Slint launcher on Android (`android-launcher`, #79). What remains for 1.0 is real-device verification and acceptance (`#67`–`#69`, `#71`, `#82`, `#83`, `#84`) plus the Mac Mini's Apple/iOS issues (`#73`–`#78`, `#121`, `#124`, `#231`, `#260`, `#264`, `#306`).

## Stages

Each stage names its platforms (R04). Stages overlap: anything not blocked can be taken. Upstream keeps moving; once a module of ours is Rust, an upstream change to the code it replaced becomes an `upstream-sync` issue that ports the change by hand.

0. **Housekeeping** (Linux, Windows, Android, iOS in CI). 0.01 the C++ unit tests (`NX_TESTS=ON`, `tests/*_test.cpp`) build and pass on GitHub's `ubuntu-24.04` runner in `check.yml` (#155), and `cpp-windows` builds C++ and the Windows player on `windows-2025` (#70 / PR #283); 0.02 the workspace cross-builds for `aarch64-linux-android` and is checked for `aarch64-apple-ios` in `check.yml` (M15); 0.03 the SPEC change for the in-app download (#229, PR #232). All done. The daily upstream sync is process; the last one is PR #246 (#145, 140 upstream commits from 2026-11-06 to 2026-11-23), which also made CI build every `*_test` target, fixed the IPC descriptor address on the iOS compact layout, and guarded `std::system` on iOS. `recomp_source_test` and `prepare/recomp` were retired in #247. Upstream's online services (`nextendo`, `hle_ssl`, `hle_hostnet`) came in as upstream has them; online play is a Won't for 1.0, and whether to switch them off in our builds is my call.
1. **Engine core: the prep tools in Rust** (Linux, Windows, macOS in CI). Each module of `crates/core` gets its final behaviour; the generic ones come from iannitram/totk-universal (MIT) with credit. Easy: 1.01 `platform` through 1.21 `hub::is_home_network`. Medium: 1.22 `prepare::step` and the stage runner; 1.22a prepare from an installed launcher; 1.22b self-contained player per hub (`assemble`); 1.23 `steam::write_shortcut` and `userdata_roots`; 1.23a–c (#152, #155, #189); 1.24 `launch::play`; 1.25 `update`; 1.26, 1.26a, 1.26b save-relay adapter, setup and whole report; 1.27 `romfs.pak` and `spirv.pak`; 1.28 `nso2bin`; 1.29 shaders and SARC; 1.29a shaders stage end to end from Rust; 1.30 message reflow; 1.30a Rust button font and glyph archives; 1.31 retire `tools/setup_acnh.py` and its Python scripts (#34 / PR #281); 1.32 fan mods (pt-BR, SpeedFix) off by default (#85). All done, including recompiler staleness hashing (#227 / PR #273), `atomic_write` (#244 / PR #245), shader translator write-xor-execute off (PR #257), and Prepare's `android` delivery target (`android_deliver` + `appgame::download`, #230 / PR #298).
2. **Faces** (Linux, Windows, macOS; Android with 9.01). 2.01 `acnh-universal` CLI; 2.02–2.02a Continue screen brief; 2.03 Slint app scaffold; 2.04–2.04d Continue screen, real relay, controller input/hot-plug/glyphs, Prepare/Pull/Update, full-screen Steam shortcut; 2.05–2.05a guided first run and relay setup; 2.06–2.06a Saves, Settings, waiting push retry and no offline play; 2.07 Fleet; 2.08 About; 2.09 release builds (AppImage, Windows zip, Mac app); 2.09a retire upstream's release packaging (`build.yml`, `tools/package_release_*.sh`, `tools/release_readme.sh`) and pin `appimagetool` (#174 / PR #288); 2.10 retire `launcher/` (SDL3 + ImGui) and `tools/launcher.sh` (#44 / PR #274). All done in code.
3. **Recompiler to Rust** (Linux, Windows, macOS in CI). `crates/recomp` takes over `recomp/` pass by pass; `tests/difftest.py` (Unicorn) stays the oracle. 3.01 `Load`; 3.02 `Analyse`; 3.03 `Emit` (integer, branches); 3.04 `Emit` (FP, NEON); 3.05 the driver (`driver.rs`, `stats.rs`), `Stage::Recompile` cut over to Rust, and `recomp/` deleted (#49 / PR #286). 4. **Runtime to Rust** (Linux, Windows, macOS, Android, iOS). 4.01 `crates/runtime` scaffold (`cbindgen`, CMake build, boot smoke test). All 11 runtime groups (`SERVICES` order) are ported to Rust (`crates/runtime/src/*.rs`) behind thin C++ ABI wrappers (`runtime/src/*_wrapper.cpp`): 4.02 `Config` (#51 / PR #276); 4.03 `Time` (#52 / PR #280); 4.04 `Saves` (#53 / PR #285); 4.05 `Files` (#54 / PR #290); 4.06 `Input` (#55 / PR #297); 4.07 `Audio` (#56 / PR #295); 4.08 `Services` (#57 / PR #302); 4.09 `Kernel` (#58 / PR #301); 4.10 `Memory` (#59 / PR #303); 4.11 `Platform` (#60 / PR #305); 4.12 `Loader` (#61). Real-device verification on the AMD handheld and target devices remains.

## Save Relay integration

I'm adopting [Save Relay](https://github.com/iannitram/save-relay) for this port's saves. It shares game saves between machines through my own Nextcloud, Google Drive or Dropbox, pulling at launch and pushing at exit, as one small Rust core reused by every game port. It is in the code now across every platform: the launcher and CLI on desktop (setup in first run and Settings, the whole report on Continue, Sync now in Saves, no play while a required sync cannot complete), the iPad's player through the same Rust API, and the Android app (9.03, #81 / PR #259, #261 / PR #265, #262 / PR #272) through Dropbox and save-relay's Android bindings, verified live on my Pixel Fold (sign-in and first pull). The Android app's game download shares that same Dropbox sign-in ("Reuse Save Relay's app"). This repo links save-relay by git, locked in `Cargo.lock` at a commit before its newest tag, the pre-release `v1.0.0-rc.2` (2026-11-18; the lock still reports 1.0.0-rc.1), and 8.08 checks that the released Mac app carries the pinned relay.

## After 1.0

The Won'ts in `SPEC.md`: local wireless play over the LAN (`docs/LOCAL_PLAY.md`, kept as upstream has it), save editing and design-pattern sync, the island's name on the save card (needs a save reader of our own), online play, Android GPUs other than Adreno (Mali), versions other than the four, above 60 FPS, and rewriting the renderer, the game code or the overlay in Rust. Upstream's Local Play and online services came in with the sync of 2026-11-23 as upstream has them; they are not 1.0 targets. The Android player already runs on the device's own Vulkan driver on other GPUs, and my Mali phone plays the game that way; making them a target is still after 1.0.

One shared `universal-core` crate for the modules every Universal port copies (#147).

A Meta Quest app for playing on a large virtual theater screen in 3D is planned after 1.0. I expect it will probably follow 2.0.

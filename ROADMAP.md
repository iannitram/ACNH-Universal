# Roadmap

From `SPEC.md` (approved 2026-11-02; M5 widened and approved again 2026-11-17) to 1.0: *Animal Crossing: New Horizons* 3.0.2, 3.0.3, 2.0.7 or 1.0.0, built from my own game folder, on the AMD handheld, the Strix Halo tablet, the RTX 3090 Ti desktop, a Mac, an iPhone or iPad, and an Adreno Android device; a week of island life on the AMD handheld (M12); the same island on each through save-relay; and our code in Rust. The code map is `docs/code-map.md`, the words are `GLOSSARY.md`, the decisions are `docs/adr/` (0001 workspace, 0002 prep tools then recompiler then runtime to Rust, 0003 Slint launcher, 0004 build hubs, 0005 Android keeps upstream's route, 0006 Apple builds the same recompiled code). Every piece is an issue titled `<id>: ...`; `Blocked by` in each issue sets the order.

## Stages

Each stage names its platforms (R04). Stages overlap: anything not blocked can be taken. Upstream keeps moving; once a module of ours is Rust, an upstream change to the code it replaced becomes an `upstream-sync` issue that ports the change by hand.

0. **Housekeeping** (Linux, Android, iOS in CI). 0.01 the C++ unit tests (`NX_TESTS=ON`, `tests/*_test.cpp`) build and pass on GitHub's `ubuntu-24.04` runner in `check.yml` (#155); 0.02 the workspace cross-builds for `aarch64-linux-android` and is checked for `aarch64-apple-ios` in `check.yml` (M15).
1. **Engine core: the prep tools in Rust** (Linux, Windows, macOS in CI). Each module of `crates/core` gets its final behaviour; the generic ones come from iannitram/totk-universal (MIT) with credit. Easy: 1.01 `platform`; 1.02 `version` (the four-version gate); 1.03 `nso` (the build id); 1.04 `gamefolder`; 1.05 `config` (`config.ini`, `launcher.ini`); 1.06 `profile`; 1.07 `recipe` (hubs, stages, outputs); 1.08 `saves` and the save-relay manifest; 1.09 `savecard`; 1.10 `backup`; 1.11 `vdf` write; 1.12 `vdf` read; 1.13 `steam` ids; 1.14 `steam` entry and upsert; 1.15 `artwork`; 1.16 `prepare::redact`; 1.17 `bundle` text and `is_forbidden`; 1.18 `bundle` manifest and verify; 1.19 `bundle::install`; 1.20 `fleet`; 1.21 `hub::is_home_network`. Medium: 1.22 `prepare::step` and the stage runner (upstream's scripts first, so a build works at every step); 1.22a prepare from an installed launcher: the source at the app's own commit inside each package, and a toolchain check per OS; 1.22b the build stage makes a self-contained player for each hub (Linux libraries, Windows DLLs; on the Mac, the one contained `ACNH-Universal.app` with MoltenVK, arm64 only); 1.23 `steam::write_shortcut` and `userdata_roots`; 1.24 `launch::play`; 1.25 `update`; 1.26 the save-relay adapter (`relay`, feature `relay`; waits on iannitram/save-relay#49); 1.26a `relay::open` from save-relay's own setup, and the setup calls (Nextcloud, Google Drive and Dropbox sign-in, `forget`), with the credential store passed in so the iPad's player uses them too; 1.26b the relay's whole report: both cards, a held island, status before Play, the card after it; 1.27 `romfs.pak` and `spirv.pak` (`pack_romfs.py`, `pack_spirv.py`); 1.28 `nso2bin` (`nso2bin.py`: LZ4 segments to a flat image); 1.29 shaders and SARC (`extract_shaders.py`, `sarc_endian.py`); 1.29a the shaders stage end to end from Rust (the .NET harness and the `blocks 0` check); 1.30 the game stage's message re-flow (`msg_rewrap.py`); 1.30a the fonts stage in Rust: the button font and a glyph archive per controller (`make_button_font.py`, `make_button_glyphs.py`), so the game's icons follow the pad in hand; 1.31 retire `tools/setup_acnh.py` and the scripts it runs (the toolchain fetch and the build stage move into `prepare`); 1.32 the fan mods (pt-BR, SpeedFix) off by default, a Settings switch each (M16).
2. **Faces** (Linux, Windows, macOS; Android with 9.01). 2.01 the `acnh-universal` CLI (`check`, `build`, `play`, `steam-add`, `fleet`; `hub` with stage 5); 2.02 the Continue screen brief, shared with totk-universal (design first: the Continue screen is the product); 2.02a the brief's save-relay states (setup, a held island, offline), text entry, glyphs for any controller, and my approval; 2.03 the Slint app scaffold with gilrs input, built in CI; 2.04 the Continue screen; 2.04a the real relay in the app, the CLI (with its `sync` command) and every release build; 2.04b controller input to the brief: stick repeat, Switch-layout pads by position, hot-plug, glyphs for the pad in hand on every page; 2.04c Continue's Prepare, Pull and Update (on the Mac hub, Prepare ends with both Apple apps in my Dropbox); 2.04d the Steam shortcut opens the app full screen in Game Mode; 2.05 the guided first run (hub: game folder, check, build, Add to Steam; client: pair, pull); 2.05a save-relay setup in the first run and in Settings; 2.06 Saves and Settings (device profile, `config.ini` values); 2.06a playing offline: the waiting push sent when the launcher opens, and sync status with Sync now in Saves; 2.07 Fleet; 2.08 About (upstream's credit, the fixes offered upstream (M8), licences, the Slint notice); 2.09 release builds (AppImage, Windows zip, Mac app) replacing `tools/package_release_*.sh`; 2.09a retire upstream's release packaging (`build.yml`'s package jobs, `tools/package_release_*.sh`) and pin `appimagetool`; 2.10 retire `launcher/` (SDL3 + ImGui) and `tools/launcher.sh`.
3. **Recompiler to Rust** (Linux, Windows, macOS in CI). `crates/recomp` takes over `recomp/` pass by pass; each pass's output matches the Python's byte for byte on hand-written AArch64 (never game code), and `tests/difftest.py` stays the oracle. 3.01 `Load` (`recomp/nso.py`); 3.02 `Analyse` (`analysis.py`, `ehframe.py`); 3.03 `Emit`, integer and branches (`emit.py`, `emit_int.py`, `regcache.py`); 3.04 `Emit`, floating point and NEON (`emit_fp.py`, `emit_neon*.py`, `emit_vldst.py`, `emit_ext.py`, `emit_sdk20.py`); 3.05 the driver (`__main__.py`, `stats.py`), the recompile stage switches to Rust, `recomp/` is deleted.
4. **Runtime to Rust** (Linux first in CI; every OS by the end). 4.01 `crates/runtime` scaffold: a static library linked into the player, its header from `cbindgen`, the C++ (renderer, `games/acnh/`, `ui/`) built through CMake from the build script, and the boot smoke test (the player reaches its first frame on a fake game library) in CI. Then one group per piece, each exporting the C symbols of the files it replaces, in `acnh_runtime::SERVICES` order: 4.02 `Config`; 4.03 `Time`; 4.04 `Saves`; 4.05 `Files`; 4.06 `Input`; 4.07 `Audio`; 4.08 `Services`; 4.09 `Kernel`; 4.10 `Memory`; 4.11 `Platform`; 4.12 `Loader` (and `main.cpp`), last. A device check on the AMD handheld follows each of 4.02-4.12 (ADR 0002).
5. **Build hubs** (Linux, Windows, macOS; Android as a client). 5.01 discovery (mDNS, private ranges only); 5.02 pairing (a six-digit code on both screens, SPAKE2); 5.03 serve and pull a bundle (sealed, resumable); 5.04 the game data a prepare made, to my own paired devices only; 5.05 fleet records over the hub and the `hub` and `fleet` commands. CI runs a fake hub on loopback.
6. **SteamOS handhelds** (Linux). 6.01 the Strix Halo tablet as hub: build from my game folder, Add to Steam, an hour from Game Mode; 6.02 the AMD handheld: install pulled from the tablet, the artwork, an hour from Game Mode; 6.03 the week on the island (M12 parts a-d, `playlog.jsonl`).
7. **Windows desktop.** 7.01 the C++ parts and the player build on GitHub's `windows-2025` runner (#155; the clang-cl and lld toolchain upstream uses; Rust target `x86_64-pc-windows-msvc`); 7.02 an hour with a controller.
8. **Mac, iPhone and iPad.** 8.01 the iOS address-space check first: does the guest's fixed 39-bit reservation (`APPLE_GUEST_SHIFT`, heap up to 6 GiB) fit an iPhone with the extended virtual addressing entitlement, and what a free Apple ID allows (7-day re-signing, memory); a written finding, then my call on the developer account; 8.02 the Mac app built natively on Apple silicon from the launcher; 8.02a the Mac's one contained app: the launcher's Prepare packs `ACNH-Universal.app` with the game prepared from my game folder inside it, read-only, into `Dropbox/_transfers/ACNH-Universal/mac/`, with saves, settings and logs in `~/Library/Application Support/ACNH-Universal`; 8.02b the player reads the game from a read-only game root inside the Apple app, and writes only to the data root; 8.03 the iOS app built on the Mac and installed by cable; 8.03e the Mac launcher makes the iPhone/iPad `.ipa` through prepare (target `ios`) into `Dropbox/_transfers/ACNH-Universal/ios/`; 8.04 iPhone and iPad controller mapping: Xbox, PlayStation and MFi controllers through Apple's GameController framework, every button mapped, touch hidden with a controller, and a controller connected or disconnected mid-game picked up; 8.05 save-relay in the iOS app, through save-relay's Rust API in the player (`acnh_core::relay`, as on the Mac and PC; owner ruling 2026-11-18: "Rust API (Recommended)"), built for `aarch64-apple-ios` at the revision in `Cargo.lock`, and my acceptance test for the Apple build, four checks on my Mac and my iPad in this order: the Mac app boots the game, I save on the Mac and the island goes up through save-relay when the game quits, the iPad app boots the game, and the iPad loads the island saved on the Mac (the way back is 8.08's); 8.05a the iPad's one app: the prepared game inside the `.ipa`, save-relay's Rust API in the player (pull, push on quit and in the background, Nextcloud setup, the conflict and held prompts), and the controller code checked; 8.06 a session on the Mac with a controller, which is disconnected mid-game and connected again and takes over without a restart; 8.07 a session on the iPad (and the iPhone) with a controller, touch controls hidden while it is connected, which is disconnected mid-game and connected again and takes over without a restart; 8.08 save-relay in the released Mac app (2.09's Mac app built with feature `relay`, save-relay pinned to a release tag; waits on iannitram/save-relay#238): a pull before the game, a push after it quits, the game still starts offline, and an island saved on the Mac continues on the iPhone or iPad and back; 8.09 Mac controller mapping: the game itself (not only the launcher's menus) takes Xbox, PlayStation and MFi controllers through Apple's GameController framework, every button mapped, and a controller connected or disconnected mid-game picked up.
9. **Android** (Adreno). 9.01 the Slint launcher's Android build in the same APK as the player, replacing `Home.java`'s folder screen; 9.01a prompts for the pad in hand on Android, in the launcher and in the game, with hot-plug; 9.02 the game library and data pulled from the Strix Halo tablet instead of `adb push`; 9.03 save-relay in the Android launcher; 9.04 a session with a controller.

## Save Relay integration

I'm adopting [Save Relay](https://github.com/iannitram/save-relay) for this port's saves. It shares game saves between machines through my own Nextcloud, pulling at launch and pushing at exit, as one small Rust core reused by every game port. Save Relay reached 1.0 on 2026-11-11 (release tag to follow). This port will adopt it for saves, so a save made on one of my machines is there on the next.

## After 1.0

The Won'ts in `SPEC.md`: local wireless play over the LAN (`docs/LOCAL_PLAY.md`, kept as upstream has it), save editing and design-pattern sync, the island's name on the save card (needs a save reader of our own), online play, Android GPUs other than Adreno (Mali), versions other than the four, above 60 FPS, and rewriting the renderer, the game code or the overlay in Rust.
